# 0003: Use local single-admin sessions for the pilot

Status: Accepted
Date: 2026-11-26

## Context

The app was originally local-only with no login. A design partner pilot needs a gate before it can run on a shared network or a small VM. The first customers are small teams using one shared workspace, not enterprises with an identity provider.

The options are a managed identity provider, a self-hosted session system, HTTP basic auth, or no auth behind a network allowlist.

## Decision

Use a self-hosted single-admin session system for the pilot.

- Passwords are hashed with Argon2id through argon2-cffi.
- Sessions are signed with itsdangerous using SHA-256 and a secret from `PAPERPROOF_SESSION_SECRET` or `data/session-secret` with mode 0600.
- Cookies are HttpOnly, SameSite=Lax, and Secure when `PAPERPROOF_ENV=prod`.
- Every state-changing form carries a per-session CSRF token.
- Failed logins lock out per IP and username for a configurable window. The limiter is in memory.
- `PAPERPROOF_AUTH_DISABLED=1` is allowed only with `PAPERPROOF_ENV=dev`.
- The admin is created with `paperproof auth set-password`.

## Consequences

Easier:

- No external identity dependency, no per-seat auth cost, and no customer data sent to an identity provider.
- Works offline and in a single container.
- The gate, CSRF, and cookie hardening are testable without a vendor sandbox.

Harder:

- One admin, no roles, no SSO, and no tenant isolation.
- Lockout counters reset on restart and do not span workers.
- Password reset is a CLI operation on the host, not a self-service flow.
- Enterprise buyers will eventually require OIDC, SAML, SCIM, and role-based access.

## Alternatives considered

- **Managed provider (Auth0, Clerk, WorkOS)**: faster SSO later, but adds cost, a vendor, and data flow review before the first pilot.
- **HTTP basic auth**: trivial, but no CSRF story, no logout, no rate limit, and poor UX.
- **Network allowlist only**: not enough for a shared VM or a remote reviewer.
